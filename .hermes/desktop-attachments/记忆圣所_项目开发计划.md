# 「记忆圣所」项目开发计划

> 版本：1.0  
> 最后更新：2026-07-28  
> 状态：方案设计阶段

---

## 一、项目概述

### 1.1 游戏名称

- **中文名**：记忆圣所
- **英文名**：Memory Sanctuary / Nar-Sil-Veth
- **副标题**：终来之刻，何物当存？

### 1.2 游戏类型

叙事驱动 · 资源管理 · 末日经营 · 碎片化考古

### 1.3 核心体验

玩家扮演"静默之翼"守护者，在行星级灾难中管理一座深埋地下的记忆圣所。时间有限、资源递减，玩家必须在终结到来前决定保存文明的哪些碎片。每一段被归档的记忆都揭示萨拉达斯文明的一个切面——而玩家的选择决定了后世"看到"的是怎样的文明。

### 1.4 目标平台

- 浏览器（HTML5 + Canvas 2D）
- 响应式设计，支持桌面与平板
- 可分发至GitHub，玩家下载后直接用浏览器游玩

### 1.5 开发周期预估

| 阶段 | 周期 | 交付物 |
|------|------|--------|
| 原型验证 | 2周 | 核心循环可玩原型 |
| MVP | 4周 | 3间存储室 + 1名守护者 + 基础系统 |
| 完整版 | 8-10周 | 12间存储室 + 5名守护者 + 完整叙事 |
| 打磨 | 2周 | 平衡调整 + 多周目 + 框架叙事 |
| **总计** | **16-18周** | |

## 二、世界观与叙事设定

### 2.1 背景框架

基于绒花计划世界观中的萨拉达斯文明与"突触震动"灾难。游戏时间跨度约为灾难第9个月至第3年（共约2.5年），即从圣所建造完成到最终封存的全过程。

**框架叙事**：游戏以绒花帝国"绿色缤球"号科研船发现圣所为外层框架。玩家"进入"圣所全息扫描数据，以守护者的视角体验一切。

### 2.2 核心场景：记忆圣所

**位置**：洛斯耶马南半球古老山脉腹地，地表以下约400米

**结构**：
- **主厅（声音殿堂）**：圆形穹顶，直径30米，中央设"歌者之座"
- **十二间存储室**：围绕主厅呈辐射状分布，每间以气密闸门隔离
- **守护者居所**：主厅一侧的小型居住单元
- **能源系统**：地热发电机 + 超大容量储电池组（设计寿命500年）

## 三、核心系统设计

### 3.1 核心循环

```
收集文明碎片（地表勘探/歌者口述/遗迹发掘）
        ↓
分配到十二间存储室（每间有容量/介质/优先级）
        ↓
消耗能源进行录入（录入过程不可逆）
        ↓
维护圣所环境（温度/湿度/辐射屏蔽）
        ↓
应对突发事件（光雨渗透/设备故障/人员变故）
        ↓
直至最终封存
```

### 3.2 资源系统

| 资源 | 说明 | 获取方式 | 消耗方式 |
|------|------|----------|----------|
| **能源** | 圣所运转的基础 | 地热发电机（持续但递减） | 录入、环境控制、设备维护 |
| **存储介质** | 含硅光学硬盘 | 初始储备+地表勘探获得 | 录入时消耗 |
| **环境稳定度** | 圣所内部环境指标 | 自动维持（消耗能源） | 光雨渗透、设备故障时下降 |
| **守护者状态** | 五名守护者的身心状态 | 休息、对话、完成归档 | 时间流逝、突发事件、资源短缺 |
| **地表可勘探度** | 外出勘探的可行性 | 随时间推移逐渐降低 | 勘探时消耗 |

### 3.3 时间系统

- **单位**：以"周"为基本单位，每"月"为一个章节，共约30个月
- **时间流逝**：每次录入操作消耗1-2周，每次勘探消耗2-3周
- **时间压力**：不直接显示倒计时，而是通过以下方式暗示：
  - 光雨侵蚀度逐渐加深
  - 地表可勘探度逐渐降低
  - 守护者对话中提及"时间不多了"
  - 某些归档条目有"过期时间"——超过某个时间点，该条目永久消失

### 3.4 归档系统

**归档条目类型**：

| 类型 | 说明 | 示例 |
|------|------|------|
| **文本文献** | 书面记录的文明内容 | 《共享公约》全文、技术文档 |
| **口述记录** | 歌者吟唱的文明记忆 | 历史编年吟唱、摇篮曲 |
| **环境录音** | 已消失世界的声音 | 森林风声、海洋潮汐 |
| **图像资料** | 视觉记录的文明碎片 | 壁画、设计图、羽毛装饰 |
| **个人遗言** | 守护者/末日的私人记录 | 守护者日志、告别录音 |

**归档流程**：
1. 发现归档条目（通过勘探/对话/事件）
2. 将条目分配至对应存储室
3. 消耗能源+存储介质进行录入
4. 录入完成后，条目永久保存，解锁对应叙事内容
5. 部分条目之间存在关联——同时归档会触发特殊对话

### 3.5 存储室系统

- 每间存储室有**容量上限**（以"数据量"为单位）
- 每间存储室有**专属色调**和**环境音特征**
- 每间存储室有**录入优先级**——优先录入的条目获得"完整保存"，后录入的可能"部分损坏"
- 存储室之间存在**隐性关联**——同时完成某些存储室会触发特殊叙事

### 3.6 突发事件系统

| 事件类型 | 示例 | 处理方式 |
|----------|------|----------|
| **光雨渗透** | 地表光雨渗入圣所，损坏设备 | 消耗能源修复 / 放弃部分存储室 |
| **设备故障** | 环境控制系统故障 | 洛恩维修（消耗时间） / 降低环境稳定度 |
| **人员变故** | 守护者生病/情绪崩溃/冲突 | 安排休息 / 对话疏导 / 强制继续工作 |
| **勘探发现** | 地表勘探带回意外发现 | 决定是否录入（消耗额外资源） |
| **能源危机** | 地热发电机输出下降 | 减少录入 / 放弃非核心存储室 |
| **介质短缺** | 存储介质储备不足 | 优先录入高价值条目 / 冒险外出搜寻 |

### 3.7 守护者互动系统

- 守护者之间会**自动产生对话**（基于当前状态、归档进度、已发生事件）
- 玩家可以**主动与守护者对话**（消耗少量时间，获得叙事信息）
- 部分对话会**影响守护者的状态**（正面或负面）
- 守护者之间的关系会随时间变化（友谊加深/分歧扩大/牺牲与传承）

### 3.8 终局系统

**终局条件**（满足任一即触发）：
- 能源耗尽
- 环境稳定度归零
- 所有守护者状态归零
- 玩家主动选择"最终封存"

**终局评价**：
- 基于已归档内容的**完整性**（数量）
- 基于已归档内容的**多样性**（覆盖多少存储室）
- 基于已归档内容的**关联性**（触发了多少关联叙事）
- 基于守护者的**最终状态**（是否都坚持到最后）

**多周目继承**：
- 已归档的条目在周目中以"后世考古发现"形式呈现
- 玩家可以尝试不同的归档策略，解锁不同叙事

## 四、美术与视觉设计

### 4.1 整体美学方向

**关键词**：暗调、琥珀色光源、声波可视化、蓝图线条、无机质感、呼吸感

### 4.2 视觉分层

#### 4.2.1 圣所主厅（核心场景）

- **构图**：圆形穹顶，等角视角或俯视角度
- **色调**：深灰/黑色背景（岩石+金属），暖琥珀色点光源
- **视觉焦点**：中央"歌者之座"——圆形平台，周围环绕声波可视化光环
- **动态元素**：
  - 歌者吟唱时，声波以可见波纹从歌者之座向外扩散
  - 存储室闸门开启时，内部透出不同颜色的光
  - 光雨侵蚀时，天花板出现裂纹，灯光闪烁

#### 4.2.2 界面UI

- **设计语言**：档案目录风格——简洁、庄重、带有萨拉达斯文字装饰
- **存储室状态**：十二个扇形图标排列，填充度表示录入进度
- **资源状态**：声波波形可视化——能源是低频波、存储介质是中频波、环境稳定是高频波
- **时间流逝**：以"光雨侵蚀度"的逐渐加深来暗示

#### 4.2.3 归档内容呈现

- 每段记忆以"档案卡片"形式出现
- 正面：标题 + 简短描述 + 分类标签
- 背面：完整文本内容 + 守护者反应对话
- 卡片设计参考"档案标签"风格

#### 4.2.4 角色表现

- **剪影+声波纹**抽象化处理
- 守护者没有具体面部表情，以剪影轮廓+周围声音波形表达情绪
- 不同守护者有不同剪影特征（缇卡的宽袍、洛恩的工装、米莎的轻便装）

### 4.3 色彩体系

| 场景/元素 | 主色调 | 辅助色 |
|-----------|--------|--------|
| 圣所主厅 | 深灰/黑 | 琥珀色（灯光）、铜绿色（金属氧化） |
| 歌者之座 | 暖白/淡金 | 声波光环的渐变蓝紫 |
| 存储室（语言） | 深蓝 | 银白 |

| 光雨侵蚀 | 病态黄绿 | 暗红（警告） |
| 框架叙事（后世） | 冷白/淡蓝 | 全息扫描的青色线条 |

## 五、音频设计

### 5.1 音频策略

**核心原则**：文本叙述为主，音频为辅。不追求复杂配乐，以环境沉浸和操作反馈为核心。

### 5.2 音频分层

| 层级 | 内容 | 来源 | 作用 |
|------|------|------|------|
| **环境音** | 地下圣所基础声景（水滴/金属吱嘎/通风嗡鸣） | 免费音效库 | 营造沉浸感 |
| **存储室音** | 每间存储室的环境音差异 | 免费音效库 | 区分空间特征 |
| **功能音效** | 录入声/闸门声/警报声 | 免费音效库 | 操作反馈 |
| **氛围音垫** | 持续低频drone | AI生成/免费素材 | 情绪底色 |

### 5.3 音频资产清单

| 音频类型 | 数量 | 说明 |
|----------|------|------|
| 圣所基础环境音 | 1段 | 循环播放，可叠加 |
| 存储室环境音 | 12段 | 每间不同，循环播放 |
| 功能音效 | 8-10个 | 短促，触发播放 |
| 氛围音垫 | 3-4段 | 不同情绪（平静/紧张/悲伤） |
| 光雨侵蚀音效 | 1段 | 随侵蚀度增强 |

### 5.4 免费音效资源

| 资源站 | 用途 |
|--------|------|
| Freesound.org | 环境音、功能音效 |
| BBC Sound Effects | 自然音效、工业音效 |
| Tabletop Audio | 氛围音垫 |
| Suno/Udio | AI生成氛围音垫（备选） |

## 六、技术架构

### 6.1 技术选型

| 层级 | 技术 | 理由 |
|------|------|------|
| **UI层** | HTML/CSS (Grid/Flex) | 档案目录、资源面板、文本内容——DOM天然适合信息密集型界面 |
| **渲染层** | Canvas 2D | 圣所主厅、声波可视化、光雨粒子——Canvas 2D足够，无需WebGL |
| **音频层** | Web Audio API | 环境音混合、功能音效触发、音频可视化 |
| **数据层** | JSON + LocalStorage | 归档进度、守护者状态、多周目数据——无需后端 |
| **构建工具** | 无（纯静态） | 直接部署至Quartz站点 |

### 6.4 关键系统实现

#### 6.4.1 Canvas渲染系统

- **圣所主厅**：分层绘制（背景层/建筑层/角色层/效果层/UI层）
- **声波可视化**：基于AnalyserNode的实时波形绘制
- **光雨粒子**：简单粒子系统，控制粒子数量以保证性能

#### 6.4.2 存档系统

- 使用LocalStorage保存游戏状态
- 支持多个存档槽位
- 导出/导入存档功能（JSON格式）

#### 6.4.3 叙事系统

- 基于条件的对话触发（时间/归档进度/事件/守护者状态）
- 对话树支持分支和循环
- 叙事标志（flags）记录玩家选择和已触发事件

## 七、开发阶段规划

### 阶段一：原型验证（2周）

**目标**：验证核心循环是否可玩、有趣

**交付物**：
- [ ] 圣所主厅基础场景（Canvas 2D）
- [ ] 1间存储室 + 3条归档条目
- [ ] 基础资源管理（能源/介质/环境）
- [ ] 1名守护者（缇卡）+ 基础对话
- [ ] 录入操作 + 归档完成反馈
- [ ] 基础UI（资源面板+存储室状态）

**验证标准**：
- 玩家能完成"发现→分配→录入→归档"的完整循环
- 资源管理产生有意义的抉择
- 归档完成时有满足感

### 阶段二：MVP（4周）

**目标**：提供可体验的完整片段

**交付物**：
- [ ] 3间存储室（语言/历史/灾难）
- [ ] 15条归档条目
- [ ] 1名守护者（缇卡）完整叙事弧线
- [ ] 基础突发事件（3种）
- [ ] 地表勘探系统（简化版）
- [ ] 框架叙事（开头+结尾）
- [ ] 基础音频（环境音+功能音效）
- [ ] 存档系统

**验证标准**：
- 30-45分钟的游戏体验
- 叙事有情感冲击力
- 系统运行稳定

### 阶段三：完整版（8-10周）

## 八、风险评估与应对

| 风险 | 可能性 | 影响 | 应对措施 |
|------|--------|------|----------|
| 叙事写作量超出预期 | 高 | 延期 | 优先完成核心条目，次要条目可后续补充 |
| 资源管理缺乏深度 | 中 | 玩法单调 | 增加事件复杂度和守护者互动 |
| Canvas性能问题 | 低 | 卡顿 | 限制粒子数量，优化渲染逻辑 |
| 音频素材不足 | 中 | 沉浸感降低 | 优先保证环境音，氛围音垫可简化 |
| 开发周期超期 | 高 | 无法完成 | MVP阶段严格验收，必要时缩减内容 |
